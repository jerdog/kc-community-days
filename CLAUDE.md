# CommunityDays KC site (communitydays.info)

## Standing requirements

- **Accessibility: WCAG 2.2 AA is the default for everything.** Every page, component and design option must meet it. In particular:
  - Text contrast at least 4.5:1 (3:1 for large text); UI parts, focus rings and meaningful graphics at least 3:1 (1.4.3, 1.4.11).
  - Visible focus on every interactive element, never hidden under a sticky header (2.4.7, 2.4.11). Use `scroll-padding-top`.
  - Pointer targets at least 24×24 CSS px (2.5.8).
  - Color is never the only cue: rooms, groups and tiers also carry a text label (1.4.1).
  - No content that blinks or animates for more than 5 seconds without a way to stop it; respect `prefers-reduced-motion` (2.2.2, 2.3.3).
  - Help (the contact email) sits in the same place on every page, in the footer (3.2.6).
  - Forms: visible labels, `autocomplete`, required fields marked in text, errors announced and tied to the field, no re-asking for data already given (1.3.5, 3.3.1, 3.3.2, 3.3.7). No puzzle CAPTCHAs (3.3.8).
  - One `h1` per page and no skipped heading levels; landmarks (`header`, `nav`, `main`, `footer`); a skip link.
  - Reflow to 320px wide without horizontal scrolling (1.4.10).
  - Run `npm run test:a11y` before committing UI changes.
- **We are not bound to the old Squarespace site's page flow or design.** Choose the information architecture that serves attendees, speakers and sponsors best.
- Owner prefers JavaScript and Cloudflare (Workers, D1, KV, R2) for anything server-side.

## Project map

- `site.config.js` (repo root): **the one file to edit** for event dates, venue, tickets, links, Sessionize event ID, lineup settings, communities, sponsors and organizers. Never hard-code years, dates, prices, counts or event names in pages; read them from `src/lib/site.js`, which derives labels, the current ticket tier and pre/post-event mode from the config.
- `src/data/sessionize.json`: generated by `npm run import:sessionize`; don't hand-edit
- `worker/index.js`: `/api/*` only; everything else is static assets from `dist/`
- `migrations/`: D1 schema as numbered SQL files. Applied automatically by `npm run deploy` (the Workers Builds deploy command) on the production branch. Never edit a deployed migration; add a new numbered file. Keep changes additive because migrations run before the new code goes live.
- `src/styles/site.css`: the whole design system (tokens at the top)
- Sponsors: tiers in `site.config.js` set the badge label, ribbon color and whether the tier is billed in the homepage hero (`hero: true`). Homepage shows sponsor badges; every page's footer shows all logos on white tiles.
- Branch previews use their own D1 database (`communitydays-preview`), set in `previews` in `wrangler.jsonc` and in `wrangler.preview-migrations.jsonc` (keep the two in sync). The Workers Builds preview command is `npm run deploy:preview`, which migrates the preview database before deploying.
- Previews: `EVENT_STATE=upcoming|past` forces the homepage mode; `SITE_TODAY=YYYY-MM-DD` builds as if it were that date (ticket tiers, mode).
- `src/lib/sessionize.js` ignores `sessionize.json` when its event ID differs from the config, so pages show "coming soon" between years. Every page must render with an empty program.

## Design direction: "Lineup" (A + B blend, approved)

- Homepage lists communities as ribbons in each community's color (order and phone cut-off set by `lineup` in `site.config.js`; default is most talks first, top 5 on phones with a "Show all" button). Tickets and speakers shown as conference badges with community ribbons.
- Ribbon shapes are drawn on a `::before` layer, never with `clip-path` on the link itself, which would clip the focus ring.
- Brand colors sampled from the logo: indigo `#303086`, gold `#fdd52f`. Community ribbon colors must pass 4.5:1 with white text and always sit beside the group's name.
- Type: Mona Sans (display, uses the width axis), Atkinson Hyperlegible Next (text), Atkinson Hyperlegible Mono (times, labels).
- Avoid the stock AI-site look: no Inter/Poppins/Space Grotesk/Bricolage, no split hero with illustration, no pill buttons or pill tags (ribbons are the site's tag shape), no rows of identical rounded shadowed cards, no offset "brutalist" shadows or tilted cards, no pastel chips, no stat-tile rows, no gradients, no emoji as icons, no default centered sections.
